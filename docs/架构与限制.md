# 架构与限制（先看这一页）

## 1. 结构

```
┌─ Steam CEF（Game Mode 的 Steam 界面）───────────────────────┐
│  Decky Loader → 本插件前端 dist/index.js（React）           │
│    · QAM 面板：状态 / 截图 / 语音 / 换模型                   │
│    · 「在 QAM 里看她」：iframe 载入 127.0.0.1:3080 的桌宠页  │
└───────────────┬─────────────────────────────────────────────┘
                │ callable / emit（Decky RPC）
┌───────────────▼─────────────────────────────────────────────┐
│ 本插件 Python 后端 main.py（deck 用户，无 _root）            │
│   · 运行时引导：Node → dsh CLI → pnpm（全在插件 runtime 里） │
│   · profile 管理：装/查 dsh-whale-girl-live2d，写人设/模型补丁│
│   · 服务调度：dsh --profile web --no-open --port 3080        │
│   · 截图 / 录音 / 转写 / headless 问答                       │
│   · 悬浮窗进程管理（Electron）                                │
└───────┬───────────────────────────────┬─────────────────────┘
        │ 子进程                         │ 子进程
┌───────▼───────────────────┐   ┌───────▼──────────────────────┐
│ dsh --profile web :3080   │   │ Electron 透明置顶窗           │
│  · DSH agent + 工具        │◄──│  载入 /dsh-pet/standalone     │
│  · dsh-whale-girl-live2d   │   │  （就是桌面上的她）            │
│  · /dsh-pet/* 路由         │   └──────────────────────────────┘
└───────────────────────────┘
```

## 2. 每个需求落在哪一层

* **截图**：后端多策略（`grim` / `spectacle` / `gnome-screenshot` / `import` / xdg 桌面门户 / Steam 截图目录监听）。
  截图落到插件 runtime 的 `screenshots/`，路径会写进提问里。
* **语音**：后端 `pw-record`（PipeWire）录 16 kHz 单声道 WAV → SIGINT 收尾 → 送 OpenAI 兼容
  `/audio/transcriptions` → 转写文本进对话。
* **游戏大师人设**：两份一起写 ——
  ① `persona.patch.yml` 里的 `- id: system-prompt` / `config.personaPrefix`（`--patch` 覆盖层，不改用户 profile 文件）；
  ② `~/dsh-deck-workspace/AGENTS.md` 里的同一段人设（带 `dsh-deck-pet:persona` 标记块，可重复生成）。
  **为什么必须两份**：web profile 的 agent preset 内有作用域 `persona` 行，会遮蔽全局 `personaPrefix`（实测踩过），
  而工作区 AGENTS.md 走 `dsh-agent-instructions` 那条通道，不受遮蔽，且只影响她自己的会话。
* **截图搜攻略**：优先走**她自己的通道** —— `POST /dsh-pet/say`（内部是官方 `sessionController.prompt`，
  有上下文记忆、她的窗口里会同步说话和做表情），回复从 `GET /dsh-pet/events`（SSE）的
  `delta`/`assistant` 事件里取；这条路不通时自动退回 `dsh --profile headless` 一次性问答。
  截图落在**她会话的工作区** `~/dsh-deck-workspace/screenshots/`，提问里用相对路径引用。
  `auto_search` 三档：`strong`（默认，先判断卡点 → 至少搜一轮 → 2-3 步做法 + 来源）、`normal`、`off`。
  实测一次强模式问答：`web_search` → `web_fetch`×2，538 个 delta 流式返回，答案带来源链接。
* **实时反馈**：她的事件流被转成 Decky 事件推到 QAM —— `stream`（边收边长字）、
  `activity`（工具调用 → 「💭 在搜攻略…」）、`answer`（说完的整段）。
* **悬浮常驻**：Electron 无边框 + `transparent` + `setAlwaysOnTop('screen-saver')`，
  120ms 轮询鼠标位置 + 页面 `DSHPet.hitTest()` 决定是否点击穿透（Linux 没有 `forward: true`，
  所以用轮询而不是 Electron 的转发）。
* **换模型**：设置页 → `model.patch.yml`（provider / model / baseURL）+ `~/.dsh/.credentials.yaml`（key, 600 权限）。

## 3. 诚实的限制（重要）

下面这些是「设计上可行、但必须在真机上确认」的点，第一次跑请照第 6 节逐一验证：

1. **QAM 里的 iframe 能不能加载 `127.0.0.1`**：Steam UI 是 CEF 页面，理论上允许 iframe，
   但如果 Steam 的 CSP 变了，面板里的桌宠会白屏。兜底：用悬浮窗看，或在 Desktop Mode 用浏览器开
   `http://127.0.0.1:3080/dsh-pet/standalone`。
2. **Game Mode 里能不能盖在游戏上**：Decky 插件 [OverLaid](https://github.com/TheLogicMaster/OverLaid)
   用同样思路（透明置顶窗 + ImGui）证明可行，但 gamescope 版本、游戏是否全屏独占会影响结果。
   盖不住时：切 Desktop Mode，或用 QAM 里的完整界面。
3. **Game Mode 自动截图**：`grim`/门户都依赖 compositor 支持，Game Mode 下大概率要退回
   `Steam + R1` + 目录监听的兜底路径。这不是 bug，是平台限制。
4. **悬浮窗里打字**：透明置顶窗拿不到稳定键盘焦点，中文输入法更麻烦。
   打字请用 QAM 里的完整界面，悬浮窗主要用来看 + 点 + 语音。
5. **`headless` 问答是无记忆的**：`dsh headless "问题"` 每次都是新会话（一次性任务）。
   所以默认走 `ask_channel: pet`（她自己的通道，有记忆、窗口里也说话），
   `headless` 只作为兜底（例如上游插件版本太老、没有 `/dsh-pet/say` 时）。
   设置里 `ask_channel` 可切；`reply_timeout`（默认 180 秒）是她多久不吭声就放弃。
6. **模型能不能「看图」取决于模型**：截图路径会作为文本给 agent，模型支持视觉就能直接看，
   不支持就得靠 OCR（例如 `tesseract`）——所以提问里写了「看不到就用 OCR」。
7. **首次下载量大**：Node ~50 MB、dsh 依赖 ~300 MB、Electron ~100 MB。全在插件 runtime 目录，
   不污染系统；SteamOS 更新也不会覆盖（因为不在只读分区里）。
8. **不用 `_root`**：后端以 `deck` 用户运行，只写 `~/homebrew/*`、`~/.dsh`、`~/dsh-deck-workspace`。
9. **端口写死 3080**：上游桌宠外壳（Windows/macOS/Linux）都认 `127.0.0.1:3080`。
   插件设置里能改端口，但改了就只在 QAM 里能用，悬浮外壳会连不上。

## 4. 上机自检清单

```bash
# 1. 插件起来了没
ls ~/homebrew/plugins/dsh-deck-pet/dist/index.js
tail -n 50 ~/homebrew/logs/dsh-deck-pet/*.log

# 2. 运行时
<插件runtime>/node/bin/node -v
<插件runtime>/dsh-tree/bin/dsh --version

# 3. 桌宠插件进 web profile 了吗
grep -n whale ~/.dsh/profiles/web/package.json

# 4. 服务
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3080/
cat "<插件runtime>/dsh-web.log" | tail -n 20      # 里面有 ?token=...

# 5. 她那一页（把 token 换成日志里的）
curl -s -H 'Cookie: dsh_pet_desk='"$(python -c 'import json;print(json.load(open("/home/deck/.dsh/dsh-live2d-pet-desktop.json"))["token"])')" \
     -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3080/dsh-pet/standalone

# 6. 截图能力
which grim spectacle gnome-screenshot import pw-record gdbus

# 7. 透明置顶窗
cat "<插件runtime>/overlay.log"
```

## 5. 后面可以怎么加

* **DSH HTTP API 直连**：把截图作为附件发进一个持久会话（这样她就有上下文、也能流式回话），
  替掉现在的 `headless` 一次性问答。
* **本地语音**：接 `whisper.cpp` / SenseVoice，做到完全离线转写。
* **多套人设**：设置页做成预设列表（游戏大师 / 陪玩 / 攻略机器人），一键切换。
* **模型热切换**：把 `model.patch.yml` 换成读写 DSH 的 settings 服务，免重启。
* **Live2D 换装**：上游插件本身支持换装，插件里加一个「换装」入口即可。
